# 路线图与待确认事项

本文件是非正式笔记, 不属于设计文档. 记录未来方向, 待确认问题与暂缓事项.
当前设计见 `docs/design.md`.

## 远期方向

- 原生插件机制: 尚未实现. 符号统一约定: 插件接口边界默认使用字符串, Symbol 不外泄; 静态链接插件与主程序共享同一驻留表; 动态加载场景由宿主在注册时传入驻留回调, 插件不得自带驻留器; 跨进程场景在薄封装层二选一: 边界走字符串, 或宿主唯一分配加插件读侧副本; 若未来引入多线程, 全进程唯一表加读写锁.
- 字节码与 JIT: 把现有线性 IR 编译为字节码; 分阶段验证, 先覆盖纯函数, 调用, 尾调用与分支, 用差分测试与原 `call` 基准确认收益; 达标后扩展到列表, Data, Actor, I/O 与环回收; 未达收益目标时保留线性解释器. 最后评估 JIT/AOT, 难点在续延与 Actor 恢复点的调用约定, 堆对象布局与运行时 ABI.
- LSP 扩展: 在现有最小 LSP 服务上补充悬停, 定义跳转与补全; 当前只发布首个类型检查或加载错误, 位置按 UTF-16 code unit 换算.
- 原生编译: 全语言单态, 无 trait 与子类型, 代码生成可使用 typed IR 或类型表; 运行时 `Value` 不需要完整类型标签. 若未来引入反射, 动态分派或跨边界动态值, 再评估运行时类型表示.
- 并行执行: 当前调度器为单线程协作式; 若未来出现多核需求, 评估工作窃取与独立环回收.
- 定时调度: cron 表达式解析与内置调度器暂不引入: 用户可在 Actor 内用 `@SetTimer` 与时间原语自行搭建调度循环. 若后续引入, 内置"下一次触发时刻"优先于内置完整调度器; 后者必须同时定死两处策略: 系统时钟被调整时的重算时机, 以及调度器被阻塞导致的错过触发是补发还是跳过. 表达式方言以 croner 一类库的常用子集为契约, `L`/`W`/`#`/`?` 等扩展不作承诺.
- 网络: 当前已实现明文 TCP 的原语层, 即监听, 接受, 连接, 按行/精确/全量读取, 写入与关闭; 网络事件由独立事件线程承载, 语言层使用 `Socket` 与 `TcpListener` 不透明句柄, 以 `SocketError` 报告可恢复失败. 后续方向: UDP, 主机名解析, TLS, 半关闭, 长度前缀分帧与更高层的 HTTP/WebSocket; 这些能力优先以原语加 `.ksl` 模块实现, 不急于引入独立标准库.
- 分布式: 分布式是远期目标之一, 网络通信与跨进程交互是语言的重要能力方向; 当前 TCP 层只提供字节流, 跨进程协议仍待设计, 见 `docs/design.md` 第 15 节; Pid 是节点内标识, 不跨进程传递. Erlang 式透明跨节点 Pid 是独立的远期议题, 牵动 Pid 身份, 消息序列化, 节点管理与故障语义, 届时再评估路线; 当前消息即语言值的设计是任何分布式方案的共同前提.

## 待确认事项

- 待确认: 通用 `Stream[T]` 与惰性迭代器. 文件流已提供, 即 `File` 句柄与按行/按块读写; 通用流暂不提供, 需要先明确实际用例与惰性求值语义, 再设计接口与运行时表示.
- 待确认: 终端原始模式的显式控制. REPL 编辑器与 `ReadLine`/`ReadKey` 每次读取时开启并恢复原始模式; 连续按键交互是否需要显式作用域开关, 以及宿主在异常退出时的恢复约定, 仍需确定.
- 待确认: `Value::Str` 是否从 `Arc<str>` 改为 `arcstr::ArcStr`. 单指针表示可把 `Value` 从 24 字节降到 16 字节, 且静态字面量零成本; 但 arcstr 更新较慢, 需要实测性能与长期维护. `smol_str` 与 `compact_str` 在 64 位上通常为 24 字节, 不适合直接替换 `Value`; `tokenizers` 面向自然语言子词切分, 不适用于编程语言词法分析.
- 待确认: 标准库的形态. 当前暂缓独立标准库, 倾向模仿 Wolfram 把常用能力作为内置函数与特殊形式提供, 由语言本身承担, 以避免跨平台模块搜索路径; 内置集合膨胀到何种程度需要在真实示例中评估.
- 待确认: 分布式 Actor 的形态. 跨进程通信统一由网络功能实现; Erlang 式透明跨节点 Pid 与显式远程消息两条路线留待分布式阶段评估.
