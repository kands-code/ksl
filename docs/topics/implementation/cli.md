# ksl 命令行与交互模式

ksl 的命令行形态, 交互模式行为与语言服务器.
语言语义见 `docs/topics/language/` 下的各篇,
模块加载见 `docs/topics/language/modules.md`.

## 1. 命令行

命令行以子命令组织, 参数解析由 `ksl-cli` 实现, 帮助与错误信息使用中文.
`ksl` 无参数显示帮助. 源文件扩展名为 `.ksl`.
不支持直接把文件作为首参数, 也不根据扩展名推断子命令.

- `ksl run <文件>` 执行脚本后退出; `ksl run --code <代码>` 直接执行代码.
  `--` 之后的参数作为脚本命令行参数, 由 `Args` 读取.
- `ksl repl [初始化文件]` 进入交互模式.
  给定初始化文件时, 先加载该文件作为主模块, 再进入交互;
  加载出错时报告错误, 并进入空环境的交互会话.
- `ksl repl --code <代码>` 在进入交互前执行一段代码.
- `run` 与 `repl` 接受 `-w` 或 `--io-workers <数量>` 指定 I/O 阻塞线程数,
  接受 `-j` 或 `--cpu-workers <数量>` 指定 CPU 调用线程数.
- `ksl lex`, `ksl ast`, `ksl cps` 与 `ksl linear` 输出各阶段的中间结果,
  `ksl check` 只做类型检查且无输出.
  `ksl cps` 输出树形续延传递风格 IR, 即 CPS IR; `ksl linear` 输出线性化基本块 IR.
- `ksl lsp` 启动语言服务器, 通过标准输入输出走 LSP.
- `ksl help [命令]` 显示帮助; `-h` 与 `--help` 等价, `-V` 与 `--version` 显示版本.

`run` 与 `repl` 在进程主线程驱动宿主, 检查与调度循环.
网络引擎与工作线程池在其他线程处理 I/O 与线程池外来调用; `Current` 类插件入口与事件泵在调度线程执行.

### 1.1 项目标记与分析根

`.kslproj` 是空文件, 只表示所在目录是项目根; 内容不读取.
标记只在启动目录检查, 不向上查找.

- `ksl run <文件>`: 模块根是被运行文件所在目录; 标记与启动目录不影响.
- `ksl check`, `ksl cps` 与 `ksl linear`: 启动目录含标记且文件位于其下时,
  模块根是启动目录; 否则是被检查文件所在目录.
- `ksl lsp`: 启动目录含标记且文档位于其下时, 模块根是启动目录;
  否则是文档所在目录. 根在启动时确定, 标记后来新增或删除需重启服务器.
- `ksl run --code` 与 `ksl repl`: 模块根是启动目录, 不读标记.

分析命令与语言服务器按模块根生成根相对模块名, 例如 `proj/lib/a.ksl` 在项目根 `proj` 下是 `lib/a`;
`run` 以文件目录为根, 同一文件是 `a`. 两种上下文不混用.

`ksl-cli` 默认启用 `lsp` 功能. 不需要语言服务器的构建可关闭默认功能:
`cargo build -p ksl-cli --no-default-features`. Android 构建采用该组合.
关闭该功能时, 顶层帮助不列出 `lsp`, 执行 `ksl lsp` 以退出码 2 提示当前构建未启用.

## 2. 退出码与错误报告

程序入口结束后, 未被显式 Join 的存活 Actor 由运行时强制终止.
入口是根模块的 `@Main`; 没有 `@Main` 时是顶层语句.

- 退出码 0 表示正常, 1 表示错误终止, `@Exit[code]` 可指定其他退出码.
- 命令行用法错误由参数解析器处理, 退出码 2, 与语言退出码无关.
- 各阶段错误带源码位置, 经 annotate-snippets 渲染输出到标准错误.
- 脚本遇首个错误即终止; REPL 出错不退出会话.

## 3. 语言服务器

`ksl lsp` 通过标准输入输出通信, 采用全量文本同步.
发布首个词法, 语法, 加载或类型检查错误; 位置按 UTF-16 码元换算.
文本变更采用防抖: 最后一次变更后停顿 300 毫秒检查,
连续输入时最迟每秒检查一次.
依赖模块未变化时复用上次检查结果; 变化按文件的修改时间与长度判断.

## 4. 交互模式

### 4.1 会话与提交

交互编辑器是终端会话的客户端, 从服务接收按键, 粘贴与尺寸事件,
不自行管理原始模式与事件源. 环境跨输入行持久.

- 求值期间调用 `ReadLine` 时, `ReadLine` 的提示照常写出, 并从同一标准输入读取下一行;
  REPL 不在这期间显示下一轮提示符.
- 程序输出与后续提示符不重叠; 进行中的程序读取优先于 REPL.
- 每次输入要么完整生效, 要么完全回滚; 运行失败时抽象机恢复全局绑定.
  两阶段提交流程见 `docs/topics/implementation/architecture.md` 第 4 节.
- 每次输入结束时类型变量必须全部解析为具体类型, 不允许把未定类型带入下一次输入.
- 结果统一以 `<编号>= ` 前缀显示, nil 也显示.
- 顶层绑定存于全局环境, 批处理与交互共用一条执行路径.
- 交互输入不是模块, 不能声明 `@Main`, `@Export` 或 `@Link`, 也不能使用 Actor 原语.
- 交互会话不注册平台事件泵.
- 结果展示中 string 与 char 始终带引号, 例如 `1= "hello"` 与 `2= 'a'`;
  格式化字符串的源码形式规则不受影响.
- 不可打印类型使用尖括号摘要, 例如 `1= <Shape>` 或 `1= <lib/math/Shape>`.
  类型名按打印位置的名义名显示; 同一真实类型有多个可见别名时,
  取声明或导入顺序中的第一个.

### 4.2 行编辑器

REPL 使用内置行编辑器.
输入采用多行缓冲: 本次输入内任意行可编辑;
编辑中以 `n$ ` 提示焦点行, 其余行按位置显示 `n> ` 与 `n| `.
接受或结束后回到普通提示符, 不再保留编辑状态.
超出终端高度时按视口窗口显示, 焦点行始终可见.

- Enter 在输入完整时整段提交, 否则在光标处拆行续输.
- Backspace 在焦点行行首合并上一行; Ctrl-D 在焦点行行尾合并下一行.
  末尾空行上的 Ctrl-D 删除该空行; 唯一空行上的 Ctrl-D 结束输入.
- 键位为 Emacs 子集: `Ctrl-A/E/B/F` 行内移动, `Ctrl-P/N` 在行间转移编辑焦点,
  `Ctrl-K/U/W/Y` 行内剪切与粘贴, `Ctrl-D`, `Ctrl-C`, `Ctrl-L`,
  `Home/End`, 方向键, `Backspace/Delete`.
  方向键上下选择历史.
  不提供补全, 灰字提示, 撤销与反向搜索.
- Tab 按键忽略: 语言没有缩进语义, 按下 Tab 不写入任何空白.
  粘贴内容中的 tab 仍按文本处理, 绘制时展开为制表位.
- 高亮按语言词法器计算, 并结合会话绑定区分内置函数, 特殊形式, 用户函数,
  原始类型, 参数化类型构造器, 命名类型与 Data 构造器;
  命名类型含内置 Data, 不透明类型与用户 Data.
  数值与字符串字面量, 注释与 `_` 另有配色.
  `@` 与 `^` 是前缀符号, 按标点配色; `/` 是类型限定名的分隔符, 按分隔符配色.
  类型限定名按词法位置区分: 斜杠前的类型限定部分按类型配色,
  斜杠后的构造器与变体名单独配色.
  模式中省略类型限定的 `/Variant` 同样命中.
- 括号按嵌套深度循环配色; 光标落在括号上或紧邻其右侧时,
  该括号与配对改为反显强调, 跨行同样有效; 没有配对时报错色.
  配对查找只走词法记号, 字符串与注释里的括号不参与.
- 历史仅保存在内存, 整段输入登记为一条.
  召回历史整段替换编辑区, 被替换的内容作为草稿保留, 翻过历史末尾时取回.
- 终端 `ReadLine` 复用单行编辑器 `LineEditor`, 只去掉历史, 高亮, 多行与续行.
  `LineEditor` 与 REPL 的 `BufferEditor` 共享 `KeyTarget` 键位映射,
  只在编辑目标上区分单行与多行; 多行拆分与焦点转移由 `BufferEditor` 处理.

### 4.3 提示符与输出

交互模式的提示符为 `n> `, 编辑中焦点行为 `n$ `,
其余续行为 `n| `, 结果为 `n= `.
接受后的回显统一显示 `n> ` 与 `n| `; `n` 在同一段输入中相同.
编号每次非空输入都前进; 失败与 REPL 命令同样占编号, 空行不占;
编号只用于标记, 不参与语义. 命令行代码算作一次输入, 占用第一个编号.

- 程序输出在交互模式的求值期间立即写出并冲刷, 终端上不滞留,
  因此先提示再读输入的程序能立刻看到提示.
- 运行时记录输出是否停在行首; 每轮输入结束时若不在行首, 补一个换行,
  使 `n= ` 独占一行.
  例如 `Print["B"]; 12` 显示为 `B` 与 `1= 12` 两行.
- 该记录是进程级的: 提示一类写出发生在 I/O 工作线程上, 同样计入;
  标准输出为终端时, 终端行规程对按行读取输入的显示也计入.
- 失败的输入没有结果标签, 补的换行使错误报告另起一行.
- 交互模式以空白行分隔区块: 输入回显, 程序输出, 结果标签或诊断,
  下一轮提示符两两之间各固定一个空白行.
  标准输出与标准错误按到达顺序混排显示, 不分区; 空行输入同样只留一个空白行.
- 初始化文件输出按同样的区块规则收尾; 有输出时, 第一个提示符前留一个空行.
- REPL 会话结束并恢复终端后才继续处理输入; 命令输出与提示符在普通模式下写出.

### 4.4 终端要求

REPL 要求标准输入与标准输出都是终端, 且终端支持 ANSI.
不满足时不加载初始化文件, 不执行命令行代码, 报告错误并以退出码 2 结束.
非交互执行使用 `ksl run`.

### 4.5 初始化文件与类型可见性

REPL 加载初始化文件时只执行顶层语句, 并保留主文件 `@Export` 的绑定;
不执行 `@Main`, 不显示主函数结果, `Print` 输出照常.
未导出的顶层绑定只作为主文件内部实现.
加载出错只影响当次加载, 会话继续.

REPL 可见的类型以会话的类型名绑定为准:

- 主文件导出的类型与行内导入的类型都以导出名或导入名可见, 类型身份取真实类型.
- 本地 `@Data` 声明的类型以本地名为准; 与已有同名类型冲突时报错.
- 只导入值而未导入类型时, 该值可以绑定与传递, 但不能匹配其变体或读取其字段.

### 4.6 会话模块缓存

REPL 的输入可以带 `@Use`, 按 `docs/topics/language/modules.md` 第 4 节的会话模块缓存规则处理.
输入内 `@Use` 在所在位置生效, 不做输入内提升;
脚本与模块文件中的 `@Use` 按同节规则提升到模块顶部.
输入中的 `@Export` 报 `ExportOutsideModule`.

## 5. REPL 命令

REPL 命令以 `%` 开头, 不属于语言语法, 只在交互模式生效.

- `%help` 显示命令.
- `%type <表达式>` 检查表达式类型.
- `%bindings` 列出全局绑定.
- `%reset` 清空会话状态.
- `%quit` 退出.

命令不设简写. 命令输出与求值结果分开显示;
`%type` 采用 `表达式 : 类型` 形式.
