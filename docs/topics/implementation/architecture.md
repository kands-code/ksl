# ksl 实现架构

ksl 解释器的内部架构, 面向实现者.
语言语义见 `docs/topics/language/` 下的各篇,
工程约束见 `docs/topics/implementation/engineering.md`.

## 1. 流水线

ksl 的流水线为词法分析, 语法分析, 类型检查, 降级为续延传递风格 IR, 即 CPS IR,
再线性化为基本块, 由线性 IR 抽象机执行. 不生成机器码.

- 执行层把 CPS IR 线性化为基本块后执行: 控制状态加去函数化的续延帧栈.
  没有操作数栈, 没有返回指令; 续延链就是栈.
- 函数调用直接替换控制状态, 尾调用不增长续延链.
  非尾调用把续延帧压入堆上的帧栈, 不消耗 Rust 原生栈.
- 运行时错误的位置由 IR 调用, 原语节点与续延帧携带的源码区间给出.
  错误不可捕获; `@Exit` 走专门通道.
- 抽象机的执行状态是纯数据. Actor 挂起时保存控制状态, 续延帧, 槽位与捕获;
  恢复时把消息值交回续延.
- `ksl cps` 输出树形 IR, `ksl linear` 输出线性化基本块 IR.
  对外稳定接口是 `Value`, 闭包, 续延与 Actor 运行时, 不是 AST 节点.
- 类型检查单趟顺序进行: 环境随语句增长, 函数体在定义处按其签名在当前环境中检查.

## 2. 闭包与递归

闭包按值捕获自由变量. `@Def` 与 `@Fix` 用写一次单元实现递归引用.
抽象机支持自递归, 互递归, 10 万层尾递归与 10 万层非尾递归.

## 3. 类型检查与降级

类型变量的身份由 ena 的并查集表示, 结构化类型统一由检查器分派.
统一器绑定存入 ena 值槽, `VarInfo` 按 `VarId` 索引为稠密数组,
`InferTy` 实现其值 trait; occurs 检查由检查器维护.
`shallow` 先于绑定求值, 因此绑定只作用于未定变量.

类型分层: `InferTy` 只存在于检查器内部, `Type` 只表示具体类型.
类型表以 `(SourceId, NodeId)` 为键; 降级器读取类型表, 按类型信息生成 IR.
值类型环境与类型别名表由 `TypeContext` 保存.

- CPS IR 携带绑定者类型与按类型信息选择的操作节点类型.
  抽象机执行时大多忽略这些字段; 闭包签名显示与名字注册原语使用其中的类型.
- 类型表覆盖降级所需的类型与位置.
- typed IR 按类型表降级: 产出只保留表示决策与函数签名的 IR.
  运行时 `Value` 只保存表示类别, 不携带完整静态类型.
- 类型信息挂在绑定者上, 即函数签名, `Let` 绑定目标, 续延参数与模式字段绑定,
  不给每个值槽重复标注. 复合值都经绑定或续延参数, 标量字面值由枚举变体自描述.
- 按类型信息选择的操作, 例如列表操作, 在操作节点自身携带完整 `Type`.
- NodeId 在解析期为每个 `Spanned` 节点分配, 只承担类型表的节点身份;
  用户可见诊断仍只用 `Span`.

## 4. CPS IR 与线性 IR

CPS IR: `cps/ir.rs` 把检查后的 AST 降级为函数级 CPS 形式.
每个函数带续延参数 `$k`; 尾调用, 普通调用, 续延绑定, `receive` 挂起点与
`continue` 都显式可见. 该树形形态是线性化的输入, `ksl cps` 输出它供调试.
IR 节点保留源码区间供运行时错误定位.

线性 IR: `cps/linear` 把 CPS 树线性化为基本块.
每个块带参数, 顺序指令与唯一终止指令.

- `Instr` 覆盖绑定, 顶层绑定与递归绑定;
  `Terminator` 覆盖返回, 跳转, 调用, 原语, 接收, 分支与 Actor 终止.
- 线性化后完成闭包转换: 分析函数自由变量, 计算基本块活跃变量,
  把变量引用解析为槽位或捕获下标, 跳转与调用显式传递活跃参数.
- 续延是目标基本块; 运行时按槽位与捕获下标取值, 不维护名字环境与续延表.
- 自由变量分析对函数引用取传递闭包: 函数值的自由变量在被引用处展开,
  再按该处的绑定集合过滤; 引用链成环时迭代到不动点.
- 块内指令连续执行, 到终止指令或预算耗尽时回到调度器; 超长基本块不会独占调度.
- 同函数块切换原地复用槽位缓冲, 非参数槽位在块内先写后读.
  被调静态已知的内置纯函数调用与同步原语不建续延帧, 直接完成并把结果送入目标块;
  需要回调用户函数或调度器效果的原语才建立续延帧.
- 纯内置调用与同步原语的续延块只有一个前驱时, 线性化后把它融合为块内指令,
  省去一次块切换; 简单实参直接替换进拼接块, 不生成参数拷贝.
- 同步原语指令标注执行后不再读取的槽位, 运行时先清空这些槽位,
  使容器实参保持唯一, 原地修改不退化为整树复制.
- `ksl linear` 输出该形态; 线性执行器是唯一后端.

编译期栈安全: CPS 降级按语句序列回卷, 自由变量分析与线性化使用显式工作栈,
释放 CPS 树时逐节点展开. 长列表字面量与长语句序列不随长度加深调用栈.

## 5. 调度器, 环回收与 I/O 执行

### 5.1 任务模型

协调器是单线程状态机: 在驱动线程上持有任务表, 就绪队列, 定时器, 等待表与收件箱.
用户代码按固定指令预算协作推进, 抽象机不使用 Rust `async fn`.
CLI 中驱动线程就是进程主线程.

```rust
struct Task { machine: Option<Machine>, place: Place, role: Role }
enum Place { Ready, Waiting, Finished }
enum Role { Prelude, Actor { handle: Arc<ActorHandle> } }
```

- 推进时任务离开任务表, 片段结束后放回; 因此没有"执行中"状态, 也不存在借出的机器.
- 挂起原因保存在 `Control::Suspend(Wait)` 中; 协调器读取后登记定时器或 Join 等待, 不复制等待原因.
- 模块顶层语句是 `Role::Prelude`; `@Main` 根 Actor 是普通 Actor, 由 `root: TaskId` 指定.
- 就绪队列不摘除失效项, 取出时按 `Place` 跳过.

| 起点      | 事件                      | 终点                 |
| --------- | ------------------------- | -------------------- |
| `Ready`   | 推进片段                  | `Finished`           |
| `Ready`   | 片段返回 `Suspended`      | `Waiting`            |
| `Ready`   | 片段返回 `Effect`         | `Ready` 或 `Waiting` |
| `Waiting` | 信箱非空, Join 结束或超时 | `Ready`              |
| `Waiting` | I/O 完成                  | `Ready`              |
| `Waiting` | 目标终止或 `@Kill`        | `Finished`           |

### 5.2 调度循环与收件箱

每轮循环依次处理: 收件箱, 释放队列, 到期定时器与延迟消息, 事件泵,
程序结局, 环回收, 然后推进 Prelude 或一个就绪任务.
每次只推进一个片段.

跨线程状态变化只经收件箱进入协调器.

```rust
enum Event {
    Io { task: TaskId, op_id: u64, result: Result<Value, Error> },
    SendWake { target: TaskId, index: usize },
    Wake,
}
```

I/O 完成, 信箱唤醒与释放队列唤醒都走该队列.
协调器本地产生的状态变化直接执行, 不入队; `@Spawn`, `@Kill`, `@Monitor`,
`@Register` 与 `@SetTimer` 在应用效果时完成.
等待事件时取最近定时器与事件泵间隔的较小值作为超时.

片段结局:

```rust
enum RunOutcome {
    Finished(Value),
    Suspended(Wait),
    Effect(Effect),
    ActorExit(ExitReason),
    Yield,
}
```

- `Suspended` 携带挂起原因; 协调器登记等待后调用 `park` 写入 `Control::Suspend(wait)`.
- 预算耗尽返回 `Yield`, 任务重新入队.
- 片段内的 panic 转为内部错误, 该任务按失败结束, 不终止进程.

### 5.3 效果与信箱

抽象机直接执行已内部同步的运行时服务; 需要调度器状态的动作返回效果请求.

| 动作                                   | 执行位置 | 原因                             |
| -------------------------------------- | -------- | -------------------------------- |
| `@Send`                                | 抽象机   | 信箱在句柄内同步, 不修改调度状态 |
| `Print`                                | 抽象机   | 输出服务支持跨线程投递           |
| `Current` 外来调用                     | 抽象机   | 在调度线程执行                   |
| `@Spawn`                               | 协调器   | 分配 Pid 与父子关系              |
| `@Kill`                                | 协调器   | 修改终止请求与等待表             |
| `@Monitor`, `@Unmonitor`               | 协调器   | 修改监视表                       |
| `@Register`, `@WhereIs`, `@Unregister` | 协调器   | 修改名字表                       |
| `@SetTimer`, `@CancelTimer`            | 协调器   | 修改延迟投递堆                   |
| `SubmitIo`                             | 协调器   | 分配操作编号并登记 I/O 等待      |
| `Io` / `Cpu` 外来调用                  | 协调器   | 提交对应线程池并挂起当前任务     |

信箱由 `ActorHandle` 内的互斥量保护, 协议如下:

- 发送方只追加消息并取走目标信箱的唤醒位; 该位原先已置位时投递 `SendWake`.
- 只有信箱所有者读取消息; 协调器唤醒时只检查信箱非空, 不取走消息.
- 接收方挂起前先置位唤醒位, 再检查信箱; 信箱为空时登记 `Wait::Receive`.
- 收到 `SendWake` 后, 协调器确认目标任务仍在等待同一信箱, 再让抽象机重试接收.
- `Io` 与 `Cpu` 调用挂起当前任务; 实参随挂起状态保存, 在操作完成前作为环回收根.

### 5.4 线程池与事件泵

每个运行时实例拥有自己的阻塞线程池, CPU 线程池, 网络引擎与标准 I/O 服务,
均按需创建, 随运行时释放.

- 文件, 目录, 子进程与 `Io` 类插件调用共用一个阻塞线程池,
  默认线程数按 CPU 核数在 4 至 16 之间取定.
- `Cpu` 类插件调用使用独立线程池, 默认线程数等于可用并行度.
- I/O 与 CPU 线程数可经命令行选项覆盖, 见 `docs/topics/implementation/cli.md` 第 1 节.
- 当前任务挂起, 完成后由协调器唤醒, 不阻塞其他 Actor.
- 线程池不提供健康检查或强制中断; 长期阻塞的读取或子进程会一直占用一个工作线程.
  调用方应避免无界阻塞, 必要时通过超时或关闭句柄结束等待.
- 插件执行类别与线程亲和性见 `docs/topics/implementation/plugins.md` 第 4 节与第 7 节.

取消只停止等待当前操作, 不保证停止已经开始的阻塞工作:

- 网络操作从引擎等待队列移除; 关闭句柄时唤醒等待中的操作.
- 文件操作无法中断; 子进程取消时终止子进程. 完成后结果由协调器丢弃.
- 标准输入请求使用协作式取消标记; 已读取但未交付的内容退回缓冲.
- 句柄释放与 `@Kill` 使用同一套取消入口.

平台事件泵由调度循环每轮调用一次; 没有其他工作时以固定间隔轮询.
交互会话不注册事件泵.

标准输入由服务的读取线程持续读取并缓冲:
终端模式走 crossterm 事件, 管道与文件模式按行缓冲, 缓冲上限 4 KB,
按未读取字节计; 单行自身超过上限时允许超限读完.
输入请求从缓冲读取, 取消不丢行.
终端所有权由服务统一管理, 包括原始模式, crossterm 事件源与 bracketed paste.
原始模式记录单一持有者; 读取在无持有者时临时进入, 有持有者时借用.

### 5.5 环回收

常规释放由 `Arc` 引用计数完成, 显式标记清扫只处理不可达环.

- 安全点只有一个条件: 调度循环不在推进片段.
- 依据是不可变容器值与标量无法独立成环; 任何环都经过 `Closure` 的捕获向量
  或 `ActorHandle` 的信箱和结果.
- 清扫对不可达闭包清空捕获, 对不可达 Actor 句柄清空信箱与结果;
  环被截断后由引用计数释放.
- 捕获向量使用可清空的内部结构; Actor 句柄的信箱与结果本身已同步.
- 候选对象以弱引用登记; 标记从调度器状态与宿主根作用域出发.
- 模块缓存导出值由宿主持有根作用域, 缓存提交时同步替换.
- REPL 每次输入开始时收集; 调度循环顶部在新登记候选对象达到阈值时收集.
  阈值默认 4096, 并随存活候选规模自适应上调; 实际触发值不低于两者较大者.
  阈值可调, 0 关闭自动收集.
- 执行中途收集使用根作用域: 回滚快照由检查点自带, 模块基环境与已执行模块的导出值
  由 RAII 守卫登记与注销.
- 不做移动或压缩, `Value` 表示不变.
- I/O 结果只包含标量, 字符串, 容器与不透明句柄, 不形成环; 未处理的完成事件不是根.

### 5.6 关闭与约束

协调器判断死锁时, 就绪任务, 线程池工作, 定时器, 释放队列与未处理事件都计为活动.
只有全部任务等待且不存在任何唤醒来源时, 才报告死锁.

关闭顺序:

1. 清空 Prelude 与 Actor 任务, 取消可取消的等待并清空定时器.
2. 冲刷输出并恢复终端.
3. 释放调度器状态; 释放队列析构时执行剩余任务.
4. 释放 I/O 与 CPU 线程池, 以及服务线程.

原生原语在一次片段内完成, 指令预算只按 IR 指令计数, 不随输入规模增长.
遍历整个容器的原语会独占调度线程, 期间定时器, I/O 完成投递, 环回收与事件泵都被推迟.
长工作应由调用方拆分, 或以 `Cpu` 类别提交到线程池.

## 6. 运行时表示

`Value` 体积为 16 字节, 大于指针的变体一律用 `Arc` 包裹.
列表用 imbl 的持久化向量并以 `Arc` 包裹;
`List[i64]`, `List[u8]`, `List[u64]`, `List[f64]`, `List[char]` 与 `List[bool]`
使用紧凑元素存储; string 用 `ArcStr`, Data 值与闭包用 `Arc` 包裹.

- 闭包捕获只克隆 `Value`, 递归定义使用写一次单元;
  用户数据不使用内部可变性.
- Actor, File 与 Socket 句柄由运行时内部同步.
- `Value` 是 `Send + Sync`; 值拷贝为 O(1); imbl 的节点级结构共享.
- 续延帧是堆上结构; ksl 递归不消耗 Rust 原生栈.
- 变体载荷不超过 8 字节; string 的 `ArcStr` 是单指针, 与判别位共占 16 字节.

## 7. 符号驻留与全局环境

符号驻留: 标识符与类型名在词法层驻留为进程内唯一的 u32, 下游统一使用 `Symbol`.

- 内表用字符串到编号的哈希表与编号到字符串的向量维护双向 1:1 查找.
- 驻留器负责索引分配, get_or_intern, resolve 与全局锁.
- 查找表按用途选择 HashMap 或 imbl 持久化映射.

IR 命名: 源码标识符, 函数名, Data 类型与变体名, 模式字段直接使用驻留 `Symbol`.
合成临时值与续延使用单调编号 `TempId` 与 `ContId`, 不进入驻留表.
函数表以 `Symbol` 为键, 显示时解析回文本.
入口函数使用源码不可表达的 `$main`, 避免与用户函数同名.
运行时全局环境只为源码名建索引, 合成临时值与续延在降级期解析为槽位与捕获下标.

全局变量按名存取于持久化全局环境; 类型检查与 IR 降级无状态;
REPL 跨行增量定义成立. 顶层绑定统一按全局存储处理, 批处理与交互共用一条路径.

## 8. 宿主生命周期

宿主生命周期集中在 `ksl-runtime::host::Host`:
宿主持有源码, 类型会话, 调度器与模块缓存; 批处理与交互共用加载, 检查, 执行与回滚流程.
宿主控制逻辑与调度循环运行在驱动线程.
需要线程亲和性的宿主应在满足要求的线程上驱动 `Host` 与 `Scheduler`.
命令行只负责参数解析, 诊断渲染与 REPL 展示.
交互输入在宿主内按两阶段提交: 类型检查在会话副本上进行,
运行成功后才提交类型环境与模块缓存.

## 9. 网络 I/O 实现

网络 I/O 由运行时拥有的网络引擎执行; 语言层句柄只持有连接编号与关闭标志.
会等待的网络原语提交操作后挂起 Actor, 完成事件经收件箱返回.

- 监听器由 socket2 创建; 非 Windows 平台开启地址复用. 引擎线程用 mio 处理事件与截止时刻.
- 等待中的网络操作在 `Wait::Io` 的根中持有目标句柄, 句柄不会在操作完成前释放.
- 默认超时是从提交开始的总时限; `ReadExact`, `ReadAll` 与 `ReadLine` 在每次等待后重新计时.
- 每个套接字分别串行化读与写; 读操作共享内部读缓冲.
- 套接字始终登记读与写兴趣; 提交操作时先立即尝试, 未完成时等待事件.
- `SocketClose` 与句柄释放设置关闭标志, 通知引擎关闭底层套接字,
  并以 `SocketError/Closed` 唤醒挂起操作.
- 调度器终止等待中的 Actor 时通知引擎移除对应操作.
- 监听器只接受显式 IP 字面量; 主机名解析与 TLS 不在当前范围内.

## 10. 外来库

`@Link` 声明由模块链接阶段收集, 并解析模块所在目录 `plugin/` 下的动态库路径.
不透明类型的身份取自该路径, 运行时不依赖插件名区分类型.
`ModuleCache` 持有 `LinkCache`, 同一规范路径只加载一次.
动态库只导出入口 `ksl_plugin_init`, 返回静态描述符;
宿主用 `libloading` 调用入口, 校验 ABI 版本与签名后直接调用统一签名的函数指针.

- 描述符列出不透明类型, 函数与全局值; 参数与返回值限标量, 字符串, `nil` 与不透明句柄.
- 字符串实参在调用期间借用, 返回字符串由宿主复制.
- 不透明句柄带类型下标与拥有标志, 拥有句柄由类型释放函数回收.
- 函数返回成功, 业务失败或内部错误; 可恢复失败映射为 `Result[T, string]`.
- ABI 布局, 执行类别, 生命周期入口与释放队列见 `docs/topics/implementation/plugins.md`.

结构体, 指针, 变长参数与回调不进入 ksl 类型系统, 由插件包装层处理.
