# ksl 实现架构

ksl 解释器的流水线, 分层与模块边界, 面向实现者.
语言语义见 `docs/topics/language/` 下的各篇,
中间表示见 `docs/topics/implementation/ir.md`,
调度器与 I/O 见 `docs/topics/implementation/scheduler.md`,
运行时表示见 `docs/topics/implementation/runtime.md`,
工程约束见 `docs/topics/implementation/engineering.md`.

## 1. 流水线

ksl 的流水线依次为词法分析, 语法分析, 类型检查与降级.
前端产出带类型的 AST, 即 typed AST. typed AST 降级为续延传递风格 IR, 即 CPS IR;
再线性化为基本块, 转为执行视图后由抽象机执行. 不生成机器码.

实现按依赖方向分层: 基础与元数据, 过程宏与插件, 诊断与执行计划, typed AST,
前端, 编译层, IR, 值表示, 宿主 I/O, 运行时, 宿主与命令行.

- 执行计划数据由 `ksl-plan` 承担; 线性 IR, 运行时与值表示共用该层.
- 前端负责词法, 语法与类型检查, 产出 `ksl-typed` 中的 typed AST.
- 编译层由 `ksl-compile` 承担模块加载, 链接与检查缓存.
- 值表示与宿主资源接口由 `ksl-value` 承担, 插件只依赖该层.
- 宿主 I/O 由 `ksl-io` 承担; 运行时经任务构造器与宿主资源使用它.
- 宿主由 `ksl-host` 承担加载, 检查, 执行与交互会话的编排.
- 错误目录与诊断渲染独立为 `ksl-diagnostics`, 只依赖 `ksl-base` 与过程宏;
  前端, 编译层, 运行时, 宿主与命令行直接依赖该层.

- 执行层把 CPS IR 线性化为基本块后执行: 控制状态加去函数化的续延帧栈.
  没有操作数栈, 没有返回指令; 续延链就是栈.
- 函数调用直接替换控制状态, 尾调用不增长续延链.
  非尾调用把续延帧压入堆上的帧栈, 不消耗 Rust 原生栈.
- 运行时错误的位置由 IR 调用, 原语节点与续延帧携带的源码区间给出.
  错误不可捕获; `@Exit` 走专门通道.
- 抽象机的执行状态是纯数据. Actor 挂起时保存控制状态, 续延帧, 槽位与捕获;
  恢复时把消息值交回续延.
- `ksl cps` 输出树形 IR, `ksl linear` 输出线性化基本块 IR.
  对外接口是 `Value`, 闭包, 续延与 Actor 运行时; AST 节点只存在于编译层.
- 类型检查单趟顺序进行: 环境随语句增长, 函数体在定义处按其签名在当前环境中检查;
  检查过程中同时构建 typed AST, 检查结束时产出 `CheckedProgram`.

## 2. 闭包与递归

闭包按值捕获自由变量. `@Def` 与 `@Fix` 用写一次单元实现递归引用.
抽象机支持自递归, 互递归, 10 万层尾递归与 10 万层非尾递归.

## 3. 类型检查与降级

### 3.1 类型表示与统一

类型变量的身份由 ena 的并查集表示, 结构化类型统一由检查器分派.
统一器绑定存入 ena 值槽, `VarInfo` 按 `VarId` 索引为稠密数组,
`InferTy` 实现其值 trait; occurs 检查由检查器维护.
`shallow` 先于绑定求值, 绑定只作用于未定变量.

类型分层: `InferTy` 只存在于检查器内部, `Type` 只表示具体类型.
值类型环境与类型名绑定由 `TypeContext` 保存.

- `Type` 与 `InferTy` 使用显式变体区分标量, `Fn`, 容器, `Pid`, `Handler`, `Data` 与 `Opaque`;
  参数化子类型用 `Arc` 共享, 克隆为 O(1).
- 两者的变体列表由 `type_shape!` 统一声明, 推断期额外带 `Var`.
- 具名 Data 与不透明类型分别用 `Data(Name)` 与 `Opaque(Name)` 表示.
- `TypeEnv` 组合 `DataTable` 与 `TypeBindings`; 后者把可见名解析为
  `TypeTarget::Data` 或 `TypeTarget::Opaque`. 内置 Data 表由 `ksl-catalog` 提供,
  前端据此建立默认 Data 表, 内置类型在默认环境中预先登记.
  模块检查的 `DataTable` 只装内置声明, 本模块声明与导入类型的声明;
  值的类型未导入时, 不能匹配其变体或读取字段.
- `TypeDeclCollector` 两趟收集 `@Data`: 先登记可见名, 再解析字段类型.
  声明名的真实身份由调用方给出, 模块内为 `模块路径/名字`, 交互会话为本地名.
- 检查器在读取类型表达式, 构造器限定名与模式限定名时按绑定解析;
  AST 保留源码中的本地名, 不在链接或导入时改写.
- 诊断渲染使用 `ksl-base` 的 `TypeNames` 快照; 会话在错误离开前附加,
  类型名按出错模块的可见名显示, 没有可见名时回退到真实身份.
- 用户错误使用 `ErrorKind` 与编号; 编译期内部错误不进入错误目录, 单独渲染.
  两者共用 `KslError`; 错误内容是装箱的薄句柄, 出错名字以 `ArcStr` 共享,
  `Result<T, KslError>` 只额外占一个指针.

### 3.2 typed AST 与降级

检查器在检查过程中按节点构建 typed AST; 检查结束时把推断类型解析为具体类型,
产出 `CheckedProgram`. typed AST 的数据结构定义在 `ksl-typed`, 检查器只负责构建与解析类型.

- `CheckedProgram` 包含顶层语句, 尾表达式与可选的模块入口 `main`.
- 类型直接挂在表达式, 绑定目标, 参数, 模式字段, Data 声明与函数签名上.
- `InferTy` 只存在于检查阶段; `CheckedProgram` 只保存具体 `Type`.
- 检查器直接返回 typed 子节点.
- `GetModuleDirectory[]` 在检查阶段展开为模块目录的字符串字面量, 运行时没有对应的内置函数.
- Data 构造器与模式记录真实类型身份; 源码中的可见名不进入降级结果.
- 降级器直接读取 typed AST.
- CPS IR 携带绑定者类型与按类型信息选择的操作节点类型.
  抽象机执行时大多忽略这些字段; 闭包签名显示使用其中的类型.
- 类型信息挂在绑定者上, 即函数签名, `Let` 绑定目标, 续延参数与模式字段绑定,
  不给每个值槽重复标注. 复合值都经绑定或续延参数, 标量字面值由枚举变体自描述.
- 按类型信息选择的操作, 例如列表操作, 在操作节点自身携带完整 `Type`.
- 用户可见诊断仍只用 `Span`.

### 3.3 模块流水线

- `ModuleUnit`: 加载阶段的解析结果与顶层 `@Use` / `@Export` / `@Link` 声明.
- `ModuleInterface`: 导入方可用的值与类型接口, 导出值的类型, 以及导出 Data 类型的声明.
- `CheckedModule`: 检查后的 typed 程序, 入口声明, 导入绑定与导入声明, 以及执行元数据.
- `ModuleInstance`: 已执行模块的导出值.
- `CompileCache` 缓存模块接口与依赖文件状态, 并记录依赖文件的修改时间与长度.
  接口携带导出 Data 类型的声明, 导入方据此建立检查环境.
  编辑器分析据此在文件变化时整体失效; 交互会话与批处理不检测.
  `InstanceCache` 缓存已执行模块的导出值与插件加载状态.
  两份缓存随会话一起提交或回滚; 根模块的接口不进入缓存.
- `CompileCache` 与 `CheckedGraph` 位于 `ksl-compile`; `InstanceCache`, 模块执行与插件加载位于 `ksl-host`.
  `RootSource` 可以携带显式根: `run` 用主文件所在目录, `check` 与语言服务器按项目标记用启动目录.

## 4. 宿主生命周期

宿主生命周期集中在 `ksl-host::Host`.
宿主持有源码, 类型会话, 调度器, 编译缓存与运行缓存; 批处理与交互共用加载, 检查, 执行与回滚流程.
宿主控制逻辑与调度循环运行在驱动线程: `Host` 与 `Scheduler` 由同一线程持有并调用, 不跨线程共享.
命令行只负责参数解析, 诊断渲染与 REPL 展示.

交互输入在宿主内按两阶段提交: 类型检查在会话副本上进行, 运行成功后才提交类型环境与两份缓存.

## 5. 外来库

`@Link` 声明由模块链接阶段收集, `ksl-host` 在运行时加载模块目录 `plugin/` 下的动态库,
以规范化路径区分插件实例. 动态库在宿主生命周期内保持映射;
插件实例随运行缓存释放, 卸载钩子不卸载代码.
描述符, 函数与类型的约定见 `docs/topics/implementation/plugins.md`.
