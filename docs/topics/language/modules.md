# ksl 模块系统

ksl 的模块组织, 导入导出规则与加载语义.
求值模型见 `docs/topics/language/evaluation.md`,
REPL 的会话行为见 `docs/topics/implementation/cli.md` 第 4.6 节.

## 1. 模块身份

文件即模块, 主文件所在目录为根目录.
`@Use` 的字符串是模块路径, 相对于当前模块文件所在目录.
实现统一追加 `.ksl`, 因此 `"lib/a"` 指向 `lib/a.ksl`, `"lib/a.ksl"` 会指向 `lib/a.ksl.ksl`.
不提供搜索路径.

`run` 执行主文件时, 根目录是主文件所在目录.
`check`, `cps`, `linear` 与语言服务器的项目根规则见
`docs/topics/implementation/cli.md` 第 1.1 节; 它们不改变 `run` 的模块根.

路径中的 `.` 与 `..` 按词法规范化, 规范化后不得越出根目录.
模块身份是规范化后的根相对路径, 完整名称不含 `.ksl`.
例如 `lib/a.ksl` 的模块名为 `lib/a`, 其中类型 `A` 的完整名称为 `lib/a/A`.
`@Link` 声明的类型例外, 其完整名称为 `$plugin/<插件文件的根相对路径>/<类型名>`.

`GetModuleDirectory[]` 返回当前模块所在目录的绝对路径, 只在模块中可用,
见 `docs/topics/library/builtins-io.md` 第 6 节.

## 2. 导入导出

`@Export` 与 `@Use` 只能出现在顶层.
`@Export[名字, ..., ^类型, ...]` 声明导出项;
`@Use[{名字, (旧名, 新名), ^类型, ^(旧名, 新名)}, "路径"]` 声明导入项.
类型条目使用 `^` 提升, 重命名条目使用配对记号.

- `@Export[]` 与 `@Use[{}, "路径"]` 合法但是空操作; 空条目 `@Use` 不加载目标模块.
- 位置不影响语义: `@Use` 在分析时视为位于模块顶部,
  `@Main` 视为位于顶层语句之后, `@Export` 视为位于模块末尾.
  源码中的实际位置保留给错误定位, `Span` 不因逻辑移动而改变.
- 导出声明只允许出现在模块中. 交互输入与 `ksl run --code` 中的 `@Export` 报 `ExportOutsideModule`.
  同一模块只允许一个导出声明, 多个导出声明报 `MultipleExportStatements`.
  `@Main` 同样只允许出现在模块中, 交互输入与 `ksl run --code` 中的 `@Main` 报 `MainOutsideModule`.
- 一个模块对同一个依赖模块最多写一次 `@Use`; 同一依赖的多个导入项放在同一个列表中.
  按规范化路径判重, 重复出现报 `DuplicateUse`.

### 2.1 外来库声明

`@Link["插件名", {^类型...}, {名字 : 类型...}]` 声明插件提供的不透明类型与值.
`@Link` 只能出现在模块中, 逻辑位置在 `@Use` 之后, 其他顶层语句之前.
声明的类型与值自动导出, `@Use` 同时查询普通导出与 Link 导出.

插件名是不含路径分隔符的普通名字, 不写扩展名.
宿主在声明所在模块的目录下查找 `plugin/` 子目录, 文件名按平台约定:
macOS 为 `lib<名字>.dylib`, Linux 为 `lib<名字>.so`, Windows 为 `<名字>.dll`.
路径按模块的规则规范化, 必须位于根目录内. 描述符中的名字必须与声明一致.

Link 类型身份为 `$plugin/<插件文件的根相对路径>/<类型名>`, 不随引用模块变化.
同一份动态库共享类型身份, 可在一个模块声明并在另一个模块的 `@Link` 签名中使用;
不同文件即使插件名相同也是不同类型.

导入的 Link 类型按插件来源与类型名解析到插件类型表, 可直接用于类型标注.
该类型出现在本模块导出值的签名中时, 仍需在本模块 `@Export` 中列出.

Link 名字在模块内不可被其他绑定重名; `@Export` 不得列出本模块 Link 声明的名字.
被 `@Use` 导入的 Link 名字属于普通导入名, 可以再次导出.

检查阶段解析插件路径并校验可恢复失败的类型, 不加载动态库.
参数与返回值按运行时值直接传递, 类型不受限制.
函数返回 `Result[T, string]` 表示可恢复失败, 插件失败以 `Result/Err[string]` 回到调用方;
错误类型不是 `string` 的 `Result` 无法映射, 在检查阶段报 `PluginUnsupportedSignature`.

模块执行时加载库, 调用 `ksl_native_plugin` 并校验描述符; 名字缺失或类型不符报运行时错误.

值可以是函数或只读全局值. 全局值在模块执行时读取一次并绑定为 ksl 值.

不透明资源由插件定义; 宿主在最后一个引用消失时析构, 资源线程安全由插件负责.
结构体, 指针, 回调与变长参数不进入 ksl 类型系统, 由插件包装层内部处理.
原生插件接口见 `docs/topics/implementation/plugins.md`.

## 3. 可见性

模块外部只能看到 `@Export` 列出的名字.
未导出的值, 类型与构造器是模块私有实现.
`@Use` 导入的名字成为当前模块的本地名字, 可以再次 `@Export`.

- 导入内容视为位于模块顶部. 本地 `@Let`, `@Def` 与 `@Fix` 可以覆盖同名导入值,
  与普通绑定遮蔽规则相同.
- 两个导入值同名时报错; 值名不支持限定形式.
- 类型导入: 本地 `@Data` 声明与导入类型重名时报错.
  同一作用域内同一个类型可见名只允许出现一次; 两个不同可见名指向同一真实类型仍允许.
- 模块内使用简化名. 本地声明的完整名称为 `模块路径/名字`.
  导入类型在导入方形成本地名, 其类型身份取真实类型 `导出方模块路径/名字`.
  `@Link` 类型的身份为 `$plugin/<插件文件的根相对路径>/<类型名>`,
  本地声明与导入都不改变它.
  类型表达式与构造器, 模式限定名在检查阶段按类型名绑定解析;
  AST 保留源码中的本地名, 类型身份始终取真实类型.
- 导出值的类型必须可见: 导出值签名中出现的全部 Data 类型与不透明类型都必须已导出或为内置类型.
  该检查递归覆盖函数参数与返回值, List, Dict, Set, Pair, Option, Result,
  Pid 的信箱与返回类型, Handler 的状态参数与 Data 字段.
  未导出类型的值不得被外部使用.
- 读取变体信息以类型可见为前提. 模式匹配与 `@DataGet` 都要求值的类型已在当前模块可见;
  只导入值而未导入类型时, 该值可以绑定与传递, 但不能匹配其变体或读取其字段.
  内置 Option 与 Result 始终可见.

## 4. 加载与执行

模块顶层按依赖顺序执行一次. 模块没有值; 最后一条表达式按普通语句检查, 非 nil 必须显式绑定或丢弃.
`@Main` 是模块入口声明, 不产生值, 不参与语句值检查; 入口蓝图由加载器内部构造.

顶层副作用, 包括 I/O, 是允许的; Actor 原语按 `docs/topics/language/actors.md` 第 4 节的词法位置规则禁止.
一次根加载内按规范化路径缓存, 同一模块只执行一次.

- 模块依赖图必须无环. 加载器用深度优先遍历标记检测,
  遇到正在加载的模块时报 `CyclicImport`, 并输出完整依赖链.
- 主文件不是被导入模块: `ksl run` 执行完整依赖树.
- `ksl repl <初始化文件>` 进入 REPL 时只暴露主文件 `@Export` 的名字,
  未导出的顶层绑定不进入交互环境.
  REPL 中的 `@Use` 相对初始化文件目录; 没有初始化文件时相对当前工作目录.
  REPL 保持首次导入的快照, 修改依赖文件后需重启 REPL;
  LSP 在依赖文件变化后重新检查.
- `ksl run --code` 中的 `@Use` 以当前工作目录为根建立一次根加载,
  依赖模块执行一次; 进程结束即丢弃缓存.
