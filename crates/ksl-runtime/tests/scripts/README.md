# 脚本测试

本目录存放 ksl 核心库的功能测试.
一个 `.ksl` 文件是一个执行用例, 用例必须正常结束; 期望值由用例内的 `@Assert` 断言给出.
断言失败即用例失败. 词法器忽略注释, 因此用例也可以直接用 `ksl run` 运行.
用例由 `crates/ksl-runtime/tests/scripts.rs` 统一驱动.

## 1. 目录

所有用例位于 `run` 下, 按能力组织文件名, 同一主题的多个断言合并到同一个脚本.
一个脚本可以包含多个场景, 由同一个 `@Main` 顺序驱动.
文件名用能力命名, 不用错误码或错误种类.

语言级错误由 Rust 测试断言 `ErrorKind`,
见 `crates/ksl-frontend/tests/errors.rs` 与 `crates/ksl-runtime/tests/runtime_errors.rs`.
脚本只覆盖可恢复的领域错误, 按错误变体断言.

## 2. 写法

- 一条断言只覆盖一个操作, 不把多条断言打包成列表或二元组.
- 表达式简短且只用一次时直接写进断言, 不建中间绑定.
  被复用或本身较长时才绑定, 绑定名说明该值的含义.
- 顶层绑定与断言直接平铺; `@Block` 只用于需要块值或需要遮蔽外层名字的场合.
- nil 值表达式直接作语句, 例如 `Print` 与 `SocketClose`, 不写成 `@Let[_, ...]`.
  非 nil 值必须绑定; 不保留结果时写 `@Let[_, 值]`.

脚本行宽不超过 96 个半角字符, 超出的折行缩进.

## 3. 与 Rust 测试的分工

只有被断言的数据在 ksl 源码层面不可见时才写 Rust 测试, 典型如词法记号序列, 类型表内容,
IR 文本形态与弱引用状态.
语言级错误路径由 Rust 测试断言错误种类, 不比较错误编号.
